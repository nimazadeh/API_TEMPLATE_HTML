# Release assembly (maintainers)

```bash
npm install
node packaging/build-release.mjs   # fresh build → release/APIForge-X-v<version>/ tree
node packaging/verify-release.mjs  # release QA audit → release/APIForge-X-v<version>/VERIFICATION.md
```

Optional: `AFX_VERIFY_DEV=1 node packaging/verify-release.mjs` also extracts
the Developer zip into a clean temp folder and proves `npm ci && npm run
build` reproduces the build.

## Resulting layout

```
release/
└── APIForge-X-v<version>/
    ├── APIForge-X-Preview.zip      ← double-click package (file://, no npm)
    ├── APIForge-X-Developer.zip    ← full Vite source package
    ├── Documentation/              ← buyer guides
    ├── README.md                   ← buyer README (copied from the repo root)
    ├── VERIFICATION.md             ← generated by verify-release.mjs
    └── PACKAGE-MANIFEST.json       ← inventory + SHA-256 per file
```

The versioned package (zips, Documentation, README, manifest, verification
report) is committed — it is the shippable deliverable. Only the transient
unpacked working folders are git-ignored (see `.gitignore`).

## How the Preview package is built

`build-release.mjs` runs a fresh `vite build`, then converts the ES-module
output into a standalone `file://` package: one classic (non-module) deferred
script per page (esbuild IIFE bundle), one standalone stylesheet with
relative font URLs, and all fonts copied to `assets/fonts/`. No CORS, no
module errors, no missing assets when double-clicked.

## Listing screenshots

```bash
npm run build
node marketplace/capture-screenshots.mjs   # → marketplace/screenshots/*.png
```

See `marketplace/SCREENSHOTS_MANIFEST.md`. Reference captures also live in
`packaging/Assets/` (see `packaging/Marketplace/Screenshot-Guide.md`).

## Version bumps

`package.json`, `packaging/CHANGELOG.md`, the repo-root `README.md` changelog
section, and the versioned release folder name (`APIForge-X-v<version>`).
